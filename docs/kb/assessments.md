# AI assessments

How rootout asks a model about an extension (scan screen, `scan --no-tui`) or an installed app. Read when touching `internal/llm`, `internal/app/inspect.go`, `internal/tui/scan.go`, `cmd/rootout/assess.go` or the setup screen's model step.

## Asking the model from the scan screen (D-036)

- **Flow.** `l` → `enqueueAssess` builds `tickedOrder()` (visible ticked first, then hidden ticked), skips answered/in-flight rows, appends the rest to `queue`, sets the flash (`asking N · M already answered`), and calls `startNext`. `startNext` pops into `pending` while `len(pending) < assessWorkers` (2), each Cmd capturing the current `assessor.Assess`; the `assessMsg` handler records the result then calls `startNext` again. The spinner tick is added only when `pending` goes from empty to non-empty.
- **Summary pane.** `detailLines` returns `summaryLines` when `tickedCount() > 1 && anyTickedAsked()`; otherwise the cursor row's detail as before. Status cell per row: verdict + confidence (`styles.verdict`), spinner `asking…`, red `error: …`, or dim `not asked`; then `firstSentence(Reasoning)`.
- **Esc / quit.** `ReviewScan` cancels the context, which stops in-flight calls; the queue is dropped with the screen.
- **Testing.** `recordingAssess()` and `feedAssess(v, cmd)` in `scan_test.go` drive the queue deterministically (`runCmd` runs batch members in order, so call order is the ask order).

## Saved answers (D-038)

- **Package.** `internal/assesscache`: `Path(env, getenv)` (`ROOTOUT_CACHE`, else `XDG_CACHE_HOME`, else `~/.cache`), `IDFor(report, provider, model)` → `EntryID` (`String()` is the map key), `Open(path)` (missing → empty; corrupt or other `version` → empty with `Unreadable()` true, replaced on the next `Store`), `Lookup` (copy with `Cached=true`), `Store` (write-through, atomic), `Len`, `Clear` (only a regular file that parses as a cache; `ErrNotCache` otherwise). Never create the file on `Open`.
- **Wiring** (`cmd/rootout/assess.go`): `openCache(provider, noCache)` returns nil for Ollama, `--no-cache`, no provider or a read error; `withCache(a, p, cache)` fills `Assess` (lookup → call → store), `Reassess` (call → store) and `Cached` (lookup only). `OnModel` reopens the cache for the new provider. `scan --no-tui` checks `Cached` first and prints `using the saved assessment` to stderr on a hit.
- **Screen** (`internal/tui/scan.go`): `preload()` on open and after `assessorMsg` (which first drops results with `Cached` and bumps `gen`; an `assessMsg` from an older generation is kept only for a row with no result yet); `L` → `enqueueAssess(force=true)` marks rows in `force` so `startNext` uses `Reassess`; `savedTag` after the model name in the verdict box and the summary cell; `L re-ask` in the footer and `?`.
- **Invalidation.** `llm.PromptVersion` + `llm.Fingerprint(report)`. When editing `prompt.go`, run the tests: `TestPromptVersionBumped` prints the new fingerprint to pin and reminds you to bump the version.
- **Testing.** `testutil.FakeHome` for the file (`assesscache_test.go`, run with `-race`); `cmd/rootout/assess_test.go` with `llm.Fake` and a temp `ROOTOUT_CACHE`; `cachedFor(id, assessment)` in `scan_test.go` for the screen.

## Reading the list (D-037)

- `verdictIcon(ri)` in `scan.go` maps a row's state to a glyph and style: pending → spinner, error → `!`, benign/malicious with `Confident()` → `✓`/`✗` in `styles.verdict`, any other assessment → `⚠`, none → blank. `llm.ConfidenceThreshold` (0.70) is the only threshold.
- `renderRow` reserves `iconW` (2) cells after the editor tag and pads by `lipgloss.Width`; when the pane is too narrow for the tag the tag is dropped first. `TestScanViewRowsExactWidth` checks every list line is exactly the pane width at 40/80/140 columns with and without icons.
- The legend (`iconLegend`) joins the header's AI line once `results` or `errs` is non-empty; the `?` overlay carries the full explanation.

## Choosing a hosted model (D-035)

- **Where the list comes from.** `anthropic.ListModels` and `openai.ListModels` call each provider's models endpoint with no retries; `Verify` is the same call without the result. Anthropic pages up to five times and drops `retired` models; OpenAI returns everything in one page, so `chatCapable` keeps `gpt-*` and `o<N>*` ids without the words `embedding, tts, whisper, dall-e, realtime, audio, image, transcribe, moderation, search, instruct`; the rule is "usable through the Responses API with a strict JSON schema" (D-013), which the search previews and legacy completions models are not. Judge future catalogue or SDK changes against that. Both sort newest first and flag deprecated models (Anthropic `lifecycle`, OpenAI `shutdown_date`). `providers.ListModels` dispatches by provider name.
- **Where the key lives.** Only in closures: `cmd/rootout/setup.go` `keyVerifier` (resolves env or Keychain, 20 s timeout) and `cmd/rootout/assess.go` `hostedLister`. `tui.SetupDeps.Verify` returns the list; `tui.Assessor.HostedModels` fetches it. Nothing in `internal/tui` stores a key.
- **The picker.** `internal/tui/hostedmodels.go` `HostedPicker`: rows are the fetched models, a synthetic `(current)` row when the configured model is absent, and `Type a model id…`. `t` jumps to typing with the current id prefilled. A fetch error shows in red with the cursor on the typing row. It implements `embeddedPicker` (`internal/tui/embedded.go`) like the Ollama `ModelPicker`, so `Setup` and `ScanView` host either through `delegate`/`closePicker`.
- **Entry points.** Setup: a verified key opens the picker (`stepModel`); esc returns to the key screen; `s` (save anyway) skips it and `SetupResult.Model` stays empty, which keeps the configured model. Scan: `m` opens the hosted picker when `Assessor.Provider` is hosted and `HostedModels` is set, else the Ollama picker; `OnModel(ctx, provider, model)` saves through `saveModel`. CLI: `rootout config models --provider anthropic|openai` prints the grid (`--json`: `{provider, current, models}`); `--pick` opens the picker and saves.
- **Persisting.** `saveModel(provider, model)` in `cmd/rootout/config.go` writes `llm.provider` and `llm.<provider>.model`; `applySetup` does the same from a `SetupResult`. `config.Save` writes the whole file, so the other provider's default name is frozen too (accepted in D-035).
- **Testing.** Adapters: `httptest` servers returning the providers' JSON (`models_test.go`). Picker: drive `HostedPicker` with `tea.KeyPressMsg`, `NewHostedPickerWith` for a list in hand, `NewHostedPicker` with a fake fetch for the spinner and error paths. Setup and scan: `recordingVerify(models, err)` and an `Assessor` with `Provider` + `HostedModels`.

## Assessing apps (D-040)

- **Facts.** `app.Inspect(ctx, env, a, run.Runner) app.Facts`: `codesign`, `spctl` and `mdls` run concurrently through the Runner under `codesignTimeout`/`spctlTimeout`/`mdlsTimeout` (vars, shortened in tests), on the `EvalSymlinks` path; parsers in `signature.go` read the output even on a non-zero exit (unsigned and rejected are answers), empty output lists the probe in `Unavailable`. Receipt, extra plist keys (`readPlistFacts` in `plist.go`) and launch items (prefix match on the bundle id under the three launchd folders) are read directly. Tests use a `fakeRunner` keyed by command name over `testdata/{codesign_*,spctl_*,mdls_*}.txt`.
- **Pipeline.** `llm.Provider` is transport only (`Complete(ctx, system, user, schema)`); `llm.Assess(ctx, p, report)` and `llm.AssessApp(ctx, p, facts)` build the prompt, call `Complete`, decode and normalise. Adapter tests call `llm.Assess`/`llm.AssessApp` against an `httptest` server and check the schema in the request (`purpose` for apps, `verdict` for extensions). `llm.Fake` picks `Result` or `AppResult` by that property and records user messages in `Calls`.
- **Prompt.** `BuildAppPrompt` (`appprompt.go`) renders one-lined sections: app, code signature, Gatekeeper, origin (URLs or "download origin unknown", added date, last-used bucket from `lastUsedBucket`), Info.plist, launch items, probes that could not run. `AppPromptVersion` + `appPromptFingerprint` are pinned by `TestAppPromptVersionBumped` (golden `testdata/app_prompt.golden`, `-update` to rewrite; the golden renders against a fixed clock through `buildAppPrompt(f, now)`).
- **Answer.** `AppAssessment{Purpose, Source, Confidence, Recommendation, Reasoning}`; `NormalizeApp` repairs enum case, percent confidence and multi-line purposes; `DecodeApp` needs a `recommendation`. `Confident()` shares `ConfidenceThreshold`.
- **Cache.** `assesscache.IDForApp(facts, provider, model)` → `AppEntryID` (`app|…|a<N>|fp`; bundle id falls back to the path), `LookupApp`/`StoreApp`; `Entry` carries `assessment` or `app`, file version unchanged. Hosted providers only (`openCache` is the single place that rule lives).
- **Wiring.** `cmd/rootout/assess.go`: `newAssessorCore` (provider, key, one cache per run, model deps, `swap`) feeds `buildAssessor` and `buildAppAssessor(ctx, env, …)`; `assessAppFunc`/`cachedAppFunc`/`withAppCache` mirror the extension hooks; `inspectFunc(env)` is the `AppAssessor.Inspect` closure over `run.Default`. `tui.AppAssessor` (`internal/tui/apps.go`) is the contract the apps screen and the picker consume.
